# 产品规格说明

版本：0.1。demo 已按本文实现 skill 指令和确定性脚本，见 `skills/chat-to-article/`。运行 `python3 skills/chat-to-article/scripts/cta.py demo` 会生成一篇样例分享包。下面的使用方式就是这个 demo 在对话里的用法。数据字段见 [架构设计](architecture.md)。

## 产品是什么

聊出文章来是安装在 Cursor 里的一个 agent skill。人用平时说话的方式下指令，skill 把某一个主题的过往聊天收成一篇文章，并在之后按段修改。

读者拿到的是一份 Markdown 和它的图。读者不安装 skill，也不需要 Cursor。

第一版没有独立网站、独立编辑器、账号体系或发布平台。工作发生在 Cursor 对话里，成品是磁盘上的文件。

## 交付形态

人实际接触三样东西。前两样留在作者自己的环境里，第三样才是交给别人的产品。

| 形态 | 是什么 | 谁拿着 | 出现时机 |
| --- | --- | --- | --- |
| 安装物 | skill `chat-to-article`：指令、共享词表、编译和扫描脚本 | 作者，随 Cursor 加载 | 安装一次 |
| 声音目录 | `~/.chat-to-article/`：风格版本、范文、私有词表、候选规则 | 只有作者 | 第一次学习风格或第一次改稿之后 |
| 文章目录 | `articles/<slug>/`：主张、大纲、正文块、图、编译稿 | 作者编辑；其中 `export/` 可交给读者 | 每写一篇就有一个目录 |

```text
作者的 Cursor
  └─ 对话（下指令、确认、逐段看）
        ├─ 读取 声音目录
        ├─ 读取 本机聊天记录 / 用户给的文件
        └─ 写入 文章目录
              └─ export/          ← 分享包：一篇 Markdown + 图
```

分享包默认包含：

- `export/article.md`：按大纲拼好的正文，没有块锚点，没有会话 id
- `export/figures/`：这篇用到的、已经接受的图

分享包默认不包含：风格档案、私有词表、主张账本、修订记录、聊天原文。

文章目录可以放在当前工作区，也可以由作者指定别的路径。声音目录可用环境变量 `CHAT_TO_ARTICLE_HOME` 改位置。换一个项目继续写时，风格还在，文章跟那一篇的目录走。

## 谁在用

| 角色 | 要完成的事 |
| --- | --- |
| 作者 | 从自己的聊天里抽出一篇可回顾的文章，改到愿意留档，需要时发给别人 |
| 读者 | 打开分享包阅读。不参与修订，不接触作者的声音目录 |

第一版只有一位作者。没有多人同时改同一篇文章的流程。

## 如何使用

在装有该 skill 的 Cursor 对话里直接说。不需要先输入 skill 名字。下面每段是一轮可以分开进行的使用，也可以在同一条对话里做完。

### 安装

实现并发布之后，把 `skills/chat-to-article/` 安装到 Cursor 能加载 skill 的位置。安装本身不产生文章，也不读取聊天记录。

共享词表随 skill 更新。私有词表和风格档案留在声音目录，更新 skill 不会覆盖它们。

### 写一篇

作者给出主题，并可以顺便指定文章放在哪。

> 把我和 agent 关于「块存储修订」的聊天整理成一篇文章。

skill 接着做这些事，每一步都把结果摊开，等作者拍板后才进入下一步：

1. **确认写作计划。** 明确文体、读者和目的，以连续偏好轴记录本篇写法，并选定行文推进方案。Agent 检查已知信息后，只对重要未知项提出选择题；状态摘要和问卷原则见 skill 参考文档。
2. **找材料。** 用主题拆成几次短检索，列出命中的会话。每一条标明「有全文」或「只有摘要」。作者勾选要纳入的会话，也可以贴上聊天摘录、指定 Markdown 或其他文件。只有摘要的会话用来提醒作者还有这段经历，不直接写成正文。
3. **确认主张。** 列出准备写进文章的事实和判断，每条带来源。作者标记接受、去掉或改写。疑似密钥会单独标出。
4. **确认大纲。** 把行文方案展开为章节顺序，以及每一处需要的图。作者调整顺序、删节、改图的类型。
5. **先看第一节。** 按作者当前的风格版本写完第一节，逐块呈现。作者接受或改写。作者若明确说「按当前风格写完」，可以一次写完其余各节。
6. **写完其余各节。** 仍然一块一块给作者看。
7. **处理词表命中。** 禁用说法标在所在句子上，只重写那一句。
8. **确认风格候选。** 这一篇里作者改过的说法，汇总成几条候选。作者决定哪些写入声音目录。写入之后版本号增加，这一篇仍使用开写时钉住的版本。
9. **导出。** 通过检查后写出 `export/`。skill 告诉作者这个目录的路径。

材料不够时停下来要来源，不先写一篇空文章。

### 改一段

过后任意一次对话里都可以继续这篇，只要说得出文章目录或标题。

> 打开文章「块存储修订」。`b003` 开头太像总结，改成直接讲问题。

skill 只改这一块，并给出这一块的前后差异。其余已接受的块保持原文。作者也可以说「这句话换成……」「这张图重画」。

作者若在编辑器里改了 `article.md`，下一次对话会按块锚点收回修改。锚点丢失时，skill 列出各块原文，请作者指出改的是哪一块。

「整篇重写」要作者明说，并再确认一次。只说「改改」时，skill 先问是改这一块、改大纲，还是改某条主张。

### 学习已有写法

> 根据 `~/writing/旧文/` 里的三篇文章学习我的写法。

skill 给出可观察到的习惯（人称、段长、标题层次）和建议当作范文的段落。作者圈定范文、接受档案差异之后，声音目录升一个版本。已经写完或正在写、并且钉住了旧版本的文章不跟着变。

还没有档案时，第一篇的修改本身就是第一批候选。作者确认后才有第一版风格。

### 维护私有词表

> 以后不要写「值得注意的是」。我习惯说「聊天记录」，不要改成「对话语料」。

前一句进入私有禁用，后一句进入私有偏好。若某个共享禁词恰是作者的习惯用语，作者可以把它放行。这些条目只存在声音目录。

### 把文章交给别人

作者把 `export/` 目录发出去：拷贝文件、或放进一个只含分享包的仓库。对方用能渲染 Markdown 和 Mermaid 的阅读器打开即可。

导出前 skill 做完这些检查才写出分享包：

- 每一块都已接受
- 用到的图都已接受，文件真实在目录里
- 共享和私有词表里的禁用项已经处理
- 标出的密钥已经由作者处理
- 作者确认这篇要不要附带主张出处；默认不附带

## 作者在对话里看到什么

| 时刻 | 呈现 |
| --- | --- |
| 找材料之后 | 会话列表，带「有全文 / 只有摘要」，以及作者补充的文件 |
| 主张 | 编号清单。每条一句话，加上来源，可逐条接受或去掉 |
| 大纲 | 章节标题、每节覆盖的主张、图位和计划使用的图格式 |
| 起草与修订 | 当前这一块的正文。修订后是这一块的差异，不是整篇重印 |
| 词表 | 命中的句子、词条、是禁用还是观察 |
| 一篇结束 | 待确认的风格候选，以及分享包路径 |
| 无法继续 | 缺什么材料、缺哪张导出的图、或哪条指令需要先澄清 |

块是一个意思完整的单元，不是一个段落。一节分几块、一块写几段、每段多长，都由内容决定，不设字数范围。

## 功能要求

| 编号 | 要求 |
| --- | --- |
| FR-1 | 作者用主题发起一篇文章，并可指定文章目录；未指定时写到当前工作区的 `articles/<slug>/` |
| FR-19 | 新文章先确认 `writing-plan.json` 中的文体、读者、目的与行文方案；未确认前不能确认主张或起草 |
| FR-20 | Agent 继续文章时读取持久化状态，向作者报告当前进度、阻塞项与可选下一步；提问优先采用有推荐项的选择题 |
| FR-21 | 被登记为全文的会话必须通过分页终止、轮数、文本消息数和截断状态核对；无法证明完整时不得标成全文 |
| FR-2 | 检索结果必须区分有全文和只有摘要。只有摘要的会话不能生成主张 |
| FR-3 | 作者可以追加文件和粘贴，作为与聊天记录同等的材料 |
| FR-4 | 主张未经作者接受，不得写进正文 |
| FR-5 | 大纲未经作者确认，不得开始起草 |
| FR-6 | 默认先完成并审阅第一节，再写后面的节 |
| FR-7 | 修订默认只改变被点名的那一块。未点名的已接受块，正文保持不变 |
| FR-8 | 主张改动后，只有引用该主张的块变为待复核；待复核的块不能进入分享包 |
| FR-9 | 整篇重写需要单独的明确指令和第二次确认 |
| FR-10 | 每篇文章创建时钉住一个风格版本，篇内修订沿用该版本 |
| FR-11 | 作者可以从既有文章学习风格；学习结果经作者接受后才升级声音目录 |
| FR-12 | 篇末把措辞修改汇总为风格候选，由作者决定是否写入。写入不改变这篇已钉住的版本 |
| FR-13 | 图按表达内容选型：结构用 Mermaid，亲手排版用 draw.io 的导出文件，数据图用 SVG，插图仅在作者明确要求时生成，网络图片带出处和许可 |
| FR-14 | draw.io 只打开编辑器。对应文件还没出现在 `figures/` 时，文章保留图位，不插入断裂图片 |
| FR-15 | 共享词表随 skill 提供。私有词表支持禁用、改用另一种说法、放行某条共享禁词 |
| FR-16 | 词表命中后重写所在句子，同块其余句子保持原样 |
| FR-17 | 分享包通过检查后才生成。默认不含声音目录、修订记录和会话出处 |
| FR-18 | 作者直接编辑带锚点的 `article.md` 后，修改能收回到对应的块 |

## 第一版的使用验收

下面每条都通过，才算第一版达到本规格。

1. 给定一个有全文会话的主题，作者完成确认后，得到 `export/article.md` 和其中引用的图文件。读者只打开这个目录就能读完。
2. 作者要求修改其中一个块之后，其他已接受块的正文与修改前一致。
3. 作者接受风格升级后，正在写的这篇仍使用原版本；新建的下一篇使用新版本。
4. 正文里仍有未处理的禁用说法时，分享包不会生成。
5. 作者没有勾选的会话，不会出现在任何主张的来源里。
6. 作者没有明确要求生图时，分享包里不会出现新生成的插图。
7. 材料只有摘要、没有全文也没有作者补充时，skill 停在要材料，不交付文章。

## 第一版不包含

- 独立的写作网站、账号、评论和多作者协作
- 自动发到博客、公众号或其他平台
- 为全部历史聊天建立向量检索
- 自动把 draw.io 画布写回文章目录
- 用生图绘制架构图或数据图
- 替作者判断项目代号、未公开人名能不能公开。这类内容只出现在导出前的确认清单里
- 读取子代理记录，除非作者点名那一次调查
- 手机端或 Cursor 以外的宿主。材料模型保持为文件，以便以后接到别的 agent；第一版的检索和生图按 Cursor 的能力实现
