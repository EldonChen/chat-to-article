# 偏好：每次反馈都沉淀下来

风格档案按篇钉住，升版只影响下一篇。本篇里作者刚教过的写法，要靠文章目录里的 `preferences.jsonl` 带到下一块。`show-block` 会把它列在风格规则前面，并注明它的优先级更高。

## 什么时候记

作者每给一次反馈，在写下一版或下一块之前先记偏好。反馈包括：

- 审阅界面里的修订和批注（`review_block` 的提交结果）；
- 选版本时的选择，以及对各版的评价（没选中的版本也算）；
- 对话里的直接指令，例如「别这么正式」「这里用我的原话」。

## 怎么记

把这次反馈归纳成 0 到 3 条能推广到别的块的写法，每条一句话，写成下一块能直接照着做的要求，并附上证据：

```bash
python3 <skill>/scripts/cta.py learn --article articles/<slug> --block b001 --source annotation \
  --text "讲经过时用我的原话，不转述成书面语" \
  --evidence "「用户提出需要按块修改」→「我说：我只想改一句」"
```

`--source` 填 `annotation`（批注）、`edit`（作者亲手改字）、`variant`（选版本时的评价）或 `chat`（对话里的指令）。

区分两类修改：

- 只对这一处成立的修改（事实更正、主张调整、这一句换个例子）不记偏好。主张变了按 [revision.md](revision.md) 走 `mark-claim`。
- 用词、句式、语气、节奏、人称、开头结尾的处理方式、段落长短、清单还是段落，这些要记。

写法要具体。「更自然一点」不能直接照着做，要写成「删掉段末的总结句」「保留口语里的转折词」这样的要求。作者的两次修改指向同一个方向时，合成一条，写得更准确。

新的偏好推翻了旧的那条时，先把旧的停用：

```bash
python3 <skill>/scripts/cta.py forget --article articles/<slug> --id p2
```

记完用一句话告诉作者，例如「记下了：讲经过时用你的原话」，方便作者当场纠正。修改当前这块时也要照着刚记下的偏好改，不要只改批注指到的那几个字。

## 写进风格档案

`learn` 同时会在声音目录的 `candidates.jsonl` 里留一条候选，所以没写进档案的偏好不会丢，下一篇出「按你的偏好」那一版时还会用到。要让它成为以后每篇都遵守的规则，需要作者确认：

- 第一节接受之后，问一次是否把本篇已记下的偏好写进风格档案。不要等整篇写完。
- 整篇结束时，再问一次剩下的。

作者确认的条目用 `bump-style` 写入，带上 `--article` 和 `--pref`，偏好会标记为已写入：

```bash
python3 <skill>/scripts/cta.py bump-style --rule "讲经过时用我的原话" --article articles/<slug> --pref p1
```

本篇钉住的 `styleRevision` 不会因此改变，但本篇的偏好早已生效，所以正在写的这篇不受影响。
