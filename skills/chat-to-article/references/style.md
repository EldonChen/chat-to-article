# 个人写作风格档案（Voice Profile）

个人风格档案保存在 `$CHAT_TO_ARTICLE_HOME`（默认 `~/.chat-to-article/`），与具体文章仓库分离：

```text
~/.chat-to-article/
  profile.json          # 当前最新风格档案
  history/
    r1.json             # 历史版本快照（供钉住旧版本的文章读取）
  lexicon/
    private.json        # 个人私有词表
  exemplars/
    e1.md               # 作者认可的本人范文片段
  candidates.jsonl      # 从各篇文章修订中收集的风格候选
```

## 一、`profile.json` 的结构

```json
{
  "revision": 1,
  "locale": "zh-CN",
  "audience": "",
  "person": "第一人称（我）",
  "structure": {
    "headingDepth": 2,
    "listPolicy": "能写成连贯句子就不拆成碎列表"
  },
  "terms": [
    {"prefer": "聊天记录", "avoid": "对话语料"}
  ],
  "exemplarRefs": ["exemplars/e1.md"],
  "rules": [
    {
      "id": "r1",
      "text": "段首落到具体场景或动作；空泛总括不要，开篇故事、悬念和段间桥要留",
      "strength": "enforce",
      "evidenceArticles": 1,
      "status": "active"
    }
  ]
}
```

- 每篇文章在创建时，将当时的 `profile.revision` 记入文章 `meta.json` 的 `styleRevision`。
- 起草和修订该文章时，读取对应版本的档案（若全局档案后来升了版，可从 `history/r<styleRevision>.json` 读取钉住的旧版）外加本篇的 `preferences.jsonl`。

---

## 二、从作者旧文学习风格

当用户提供几篇自己过去写的文章（如 `~/writing/*.md`）希望系统学习其文风时：
1. **由你（Agent）直接阅读旧文做深度文风归纳**（不要依赖机械字数统计）：
   - 观察其人称习惯、开头切入方式（是从具体故障/故事切入还是先给定义）、段落节奏、转折与连接词习惯、标题层级密度、是否爱用类比或代码对照；
   - 挑选 2–3 段最具代表性的原文作为候选范文片段（`exemplars`）。
2. **交由作者确认**：
   - 将归纳出的具体风格规则与范文片段展示给作者（有 `review_style_candidates` 工具时可直接调用）。
3. **升级档案版本**：
   - 作者确认后，将原 `profile.json` 备份到 `history/r<旧版本号>.json`，把 `revision` 加 1，写入新确认的 `rules` 和 `exemplars/`。

---

## 三、篇末沉淀风格候选

在一篇文章写完（或第一节审完）时，可整理本篇 `preferences.jsonl` 中尚未升级（`promoted: false`）的规则以及 `revisions.jsonl` 中反映出的措辞偏好，询问作者是否写入全局风格档案（可调用 `review_style_candidates`）。
- 若环境使用 `review_style_candidates`，用户在界面上勾选提交后，组件会自动完成 `profile.json` 的版本递增与 `history/` 快照保存。
- 未被勾选的条目可保留在 `candidates.jsonl` 中，不强行写入全局规则。

---

## 四、优先级顺序

当不同来源的风格要求发生冲突时，按以下从高到低的优先级执行：
1. 作者在当前对话或当前块批注里的**明确指令**；
2. 本篇刚沉淀的偏好（`articles/<slug>/preferences.jsonl`）；
3. 个人私有词表（`~/.chat-to-article/lexicon/private.json`，包含对共享禁词的 `allow` 放行）；
4. 本篇钉住的个人风格档案（`profile.json` / `history/r<N>.json`）；
5. 本篇选定的内置笔调（`writing-plan.json` 的 `voice`）；
6. 共享词表（`<skill>/lexicon/`）。

科普体裁下，推演契约（冷开场的输入输出对比、带数值的逐步推演、段间桥）高于档案里的「不写铺垫 / 段首只给问题」。那些规则只用来删空泛总括和套话，不能用来删掉材料里的数字、状态和反例，也不能把「材料里有没有」写进正文。

---

## 五、术语出现在推演之后

每个新术语按这个顺序出现：

1. **直白定义加一组输入输出**：这个东西是什么，没有它和有它各吐出什么。
2. **一步推演**：这一步开始时的状态、规则如何作用、关键量在作用前后各是多少。
3. **名字**：挂在这一步后面，并马上用回同一步的数，不要换成另一个场景。

同行体裁只有在读者假设被作者明确确认后，才可以省掉第 1 步。默认科普读者没有这个豁免。

---

## 六、一句判断，禁止比喻反客为主

科普正文记住的是一句技术判断，写在 `goldenThread`。每一节只给这句话补一步，不要平行再开一条结论。

`extendedMetaphor` 不再是必填，也不再要求全文维持一套生活隐喻。机制段的主语是材料里的技术实体：系统、状态、输入、输出、规则作用前后的量。生活隐喻若出现，只能是机制算完之后的半句，而且删掉这半句之后推演仍然成立。柜台、申报表、柜员、盖章、落笔、换油墨这类说法若承担了解释任务，这一维记 0 分。

禁止为了去掉 AI 腔另起比喻。词表里的「恰似 / 宛如 / 好似」和句式「仿佛 / 犹如」是观察项：命中就改成直接叙述。观察项不阻断导出。

## 七、冷开场，禁止第一段抢跑

第一幕的第一段只有两样东西，按这个顺序：

1. 一个读者能站进去的使用场景，以及同一输入的两组输出。没有这项技术时拿到什么，有它时拿到什么，都要在这一段里看得见。
2. 紧接着的一句大白话定义：这个技术是什么，解决哪一个具体问题。

第一段以及它前面的任何句子，禁止写全篇判断、原理综述、术语清单或「一共有几层」。分层预告只出现在最后一拍。定义不能跑到输入输出对比的前面。开篇这组字段和取值一直用到结尾。后文要换一种更松的约束时，先写「同一道请求，把约束放宽成……」，再给输出。不要无铺垫换成另一组名字。

## 八、正文不提聊天

成稿是给读者看的文章。材料里的追问写成「我一开始以为……」，推导写成「把这一步摊开算……」。不要写「聊天里把它收成一句判断」「摘录在这个状态下列出」「聊天没有给出」「聊天写到这里就断了」「下面这组分数聊天里没有」。

材料里没写完的实现细节只记在 `knowledgeGaps`。正文不要接着解释缺了哪一个数。

`pat-fourth-wall` 是 `ban`。正文出现「聊天里」「对话中」「摘录里」「摘录没有」「聊天写到」「聊天没有」「聊天后文」时，先改成第一人称现场，再导出。

## 九、两张表不要并成一张

数值推演和能力对比是两张表。有了前一张，不能删后一张。

**单步状态与数值表**放在机制步。列是：

| 输入状态 | 候选 | 原始数值 | 约束动作 | 归一化后 |
| --- | --- | --- | --- | --- |
| 这一步的状态名 | 材料里的候选 | 材料里的原始数 | 保留或排除 | 材料里的结果 |

每一行都要能单独把这一步算完。不要留空单元格，也不要在表下补一句，解释某一格为什么空着。材料里如果只有重归一化之后的概率，就不要做这张五列表，用一句话写明概率集中在允许集上。不要丢掉材料里已经完整的算例，再自编一组假设数字。补不齐的候选不进表，也不在正文里交代它缺了什么。`pat-missing-value` 是 `ban`：正文不得出现「没有在同一次计算」「未约束概率没有给出」「没有给出」，也不得用「确定得了……确定不了……」这种审计句。

**机制能力对比表**在材料比较过不同约束形式时必须单独出现。它回答「这种文法表达得了什么」，列是：

| 机制层级 | 能锁住什么 | 锁不住什么 |
| --- | --- | --- |
| 局部模式或有限状态 | 材料里它真正卡住的那一类形状 | 同一个案例里它放行的那个反例 |
| 嵌套结构或栈 | 材料里它能递归表达的那一类 | 同一个案例里它仍不管的那个值 |
| 类型契约 | 材料里它核过的字段和类型 | 同一个案例里类型通过、含义不通的那个值 |

锁不住的那一格必须是全文这个案例里已经出现或紧接着出现的具体输出，不要另编一道题。这张表不回答「交出去之前还要过哪几道检查」。验收分层是第五拍的另一张表，列是：验收层、它保证什么、它不保证什么。两张表的行不能混写，也不能互相代替。

## 十、先指认例子，再挂符号

材料里的形式化符号（集合名、函数、下标）不能先于例子出现。读者先要能指着前文已经见过的三个具体输出：模型爱写但语法不收的那个，语法放行但不是这道题答案的那个，任务真正要的那个。然后用一句话把符号挂上去。

同一段落里新引入的形式化符号不超过 3 个。一段里连续定义一串符号，先拆开，把每个符号放回它对应的那个例子后面。

## 十一、句子跟着因果走

第一人称复盘不是把判断拆成一行一行的条目。下一句要接住上一句的因果或转折，例如「换句话说」「但问题恰恰出在这里」「一旦把规则放宽到……」。连续三句以上都没有这类连接，就改写，不要保留成电报。连接词是为了把同一道题往下推，不是为了凑语气。全篇仍是开篇那一个案例。
