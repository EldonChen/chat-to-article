# 个人写作风格档案（Voice Profile）

个人风格档案保存在 `$CHAT_TO_ARTICLE_HOME`（默认 `~/.chat-to-article/`），与具体文章仓库分离：

```text
~/.chat-to-article/
  profile.json          # 当前最新风格档案
  history/
    r1.json             # 历史版本快照（供钉住旧版本的文章读取）
  lexicon/
    private.json        # 个人私有词表
  exemplars/
    e1.md               # 作者认可的本人范文片段
  candidates.jsonl      # 从各篇文章修订中收集的风格候选
```

## 一、`profile.json` 的结构

```json
{
  "revision": 1,
  "locale": "zh-CN",
  "audience": "",
  "person": "第一人称（我）",
  "structure": {
    "headingDepth": 2,
    "listPolicy": "能写成连贯句子就不拆成碎列表"
  },
  "terms": [
    {"prefer": "聊天记录", "avoid": "对话语料"}
  ],
  "exemplarRefs": ["exemplars/e1.md"],
  "rules": [
    {
      "id": "r1",
      "text": "段首落到具体场景或动作；空泛总括不要，开篇故事、悬念和段间桥要留",
      "strength": "enforce",
      "evidenceArticles": 1,
      "status": "active"
    }
  ]
}
```

- 每篇文章在创建时，将当时的 `profile.revision` 记入文章 `meta.json` 的 `styleRevision`。
- 起草和修订该文章时，读取对应版本的档案（若全局档案后来升了版，可从 `history/r<styleRevision>.json` 读取钉住的旧版）外加本篇的 `preferences.jsonl`。

---

## 二、从作者旧文学习风格

当用户提供几篇自己过去写的文章（如 `~/writing/*.md`）希望系统学习其文风时：
1. **由你（Agent）直接阅读旧文做深度文风归纳**（不要依赖机械字数统计）：
   - 观察其人称习惯、开头切入方式（是从具体故障/故事切入还是先给定义）、段落节奏、转折与连接词习惯、标题层级密度、是否爱用类比或代码对照；
   - 挑选 2–3 段最具代表性的原文作为候选范文片段（`exemplars`）。
2. **交由作者确认**：
   - 将归纳出的具体风格规则与范文片段展示给作者（有 `review_style_candidates` 工具时可直接调用）。
3. **升级档案版本**：
   - 作者确认后，将原 `profile.json` 备份到 `history/r<旧版本号>.json`，把 `revision` 加 1，写入新确认的 `rules` 和 `exemplars/`。

---

## 三、篇末沉淀风格候选

在一篇文章写完（或第一节审完）时，可整理本篇 `preferences.jsonl` 中尚未升级（`promoted: false`）的规则以及 `revisions.jsonl` 中反映出的措辞偏好，询问作者是否写入全局风格档案（可调用 `review_style_candidates`）。
- 若环境使用 `review_style_candidates`，用户在界面上勾选提交后，组件会自动完成 `profile.json` 的版本递增与 `history/` 快照保存。
- 未被勾选的条目可保留在 `candidates.jsonl` 中，不强行写入全局规则。

---

## 四、优先级顺序

当不同来源的风格要求发生冲突时，按以下从高到低的优先级执行：
1. 作者在当前对话或当前块批注里的**明确指令**；
2. 本篇刚沉淀的偏好（`articles/<slug>/preferences.jsonl`）；
3. 个人私有词表（`~/.chat-to-article/lexicon/private.json`，包含对共享禁词的 `allow` 放行）；
4. 本篇钉住的个人风格档案（`profile.json` / `history/r<N>.json`）；
5. 本篇选定的内置笔调（`writing-plan.json` 的 `voice`）；
6. 共享词表（`<skill>/lexicon/`）。

科普体裁下，六幕推演（痛点与定义、两个误区、单步解码、文法引擎、语法不等于答案、分层收束）高于档案里的「不写铺垫 / 段首只给问题」。那些规则只用来删空泛总括和套话，不能用来删掉使用场景、输入输出、状态、数值、能力对比和结尾回顾，也不能把「材料里有没有」写进正文。

---

## 五、术语出现在推演之后

每个新术语按这个顺序出现：

1. **直白定义加一组输入输出**：这个东西是什么，没有它和有它各吐出什么。
2. **一步推演**：这一步开始时的状态、规则如何作用、关键量在作用前后各是多少。
3. **名字**：挂在这一步后面，并马上用回同一步的数，不要换成另一个场景。

同行体裁只有在读者假设被作者明确确认后，才可以省掉第 1 步。默认科普读者没有这个豁免。

---

## 六、一句判断，禁止比喻反客为主

科普正文记住的是一句技术判断，写在 `goldenThread`。每一节只给这句话补一步，不要平行再开一条结论。

`extendedMetaphor` 不再是必填，也不再要求全文维持一套生活隐喻。机制段的主语是材料里的技术实体：系统、状态、输入、输出、规则作用前后的量。生活隐喻若出现，只能是机制算完之后的半句，而且删掉这半句之后推演仍然成立。柜台、申报表、柜员、盖章、落笔、换油墨这类说法若承担了解释任务，这一维记 0 分。

禁止为了去掉 AI 腔另起比喻。词表里的「恰似 / 宛如 / 好似」和句式「仿佛 / 犹如」是观察项：命中就改成直接叙述。观察项不阻断导出。

## 七、六幕路标，而不是哑谜标题

每一节的标题都要让没读过正文的人知道这一节回答什么、结论是什么。可以用「掩码发生在 Softmax 之前，不是整段写完再改」。不可以用「我一开始以为……」或半截引语当标题。

六幕的顺序和内容以 [SKILL.md](../SKILL.md) 的六幕为准。第一幕用「你」起句，先写那个抓狂时刻，再给定义和两组输出，并留下全文的主线问题。不要把第一句写成一个孤立的代码片段，也不要写成「开发者把……」。

第二幕回答两个问题：改的是权重还是推理时的拦截，拦截发生在每一个词之前还是整段写完之后。第六幕必须有五层表和一段按顺序的回顾。删掉结尾来躲避「综上所述」是不合格的。这两个词只是观察项，结尾该写就写，但回顾里要有具体的层和步骤，不能只剩套话。

开篇的那组输入和取值用到最后一幕。中途放宽格式时，先写仍是同一道请求。

## 八、正文不提聊天

成稿是给读者看的文章。不要写「聊天里把它收成一句判断」「摘录在这个状态下列出」「聊天没有给出」「聊天写到这里就断了」。

材料里没写完的实现细节只记在 `knowledgeGaps`。正文不要接着解释缺了哪一个数。

`pat-fourth-wall` 是 `ban`。正文出现「聊天里」「对话中」「摘录里」「摘录没有」「聊天写到」「聊天没有」「聊天后文」时，先改成读者能跟着走的讲解，再导出。

## 九、三张表各管一件事

**单步状态与数值表**放在第三幕，而且要两张。列都是输入状态、候选、原始数值、约束动作、归一化后。每一行都要能算完。不要留空单元格，也不要在表下解释某一格为什么空着。`pat-missing-value` 是 `ban`。

第一张：允许集里只剩一个有限分数，归一化结果是 1，其余被写成负无穷的候选是 0。第二张：多个有限分数一起重归一化，而且胜出者不是原始第一名。材料里原始排第一的非法高分词写成负无穷，排在后面的合法词留下并成为允许集上的第一名。两行都要进这张表。禁止用「若把状态改成……」代替第二张表。材料里没有第二组完整分数时不要编；有这组分数却不列表，第三幕不算写完。

同一幕还要写一件容易跳过的事：不能先取概率最高的若干个再过滤，因为合法 token 可能不在里面。

**文法能力对比表**放在第四幕，不并进第五幕。列是机制层级、数据结构、能锁住什么、锁不住什么。三行分别是正则或有限状态自动机、上下文无关文法或下推自动机、JSON Schema 编译出的文法。锁不住的格子用全文同一个案例的具体输出。

**五层验收表**只放在第六幕。五行是：语法生成、结构契约、业务语义校验、意图编译成窄契约、执行前检查。每一行写保证什么、不保证什么。表后面是回顾全文的一段话。

## 十、先指认例子，再挂符号

第五幕先给出两个看得见的输出：过宽的文法放行的那句导语，以及类型合法但数值荒谬的那个字段。然后再用一句话挂上三个集合：模型偏好、文法允许的集合、任务要的答案。同一段新符号不超过 3 个。

## 十一、句子跟着因果走

讲解不是把判断拆成电报，也不是旁观说明书。下一句接住上一句的因果或转折，例如「换句话说」「但问题恰恰出在这里」「一旦把规则放宽到……」。幕与幕之间直接对读者说：「你肯定遇到过这种抓狂时刻」「顺着这个思路往下想，第一个直觉问题就来了」「看到这儿你可能会问」。连续三句以上都没有这类连接，就改写。

不要用「开发者把……」「读者接着会问……」「主线问题要先拆成……」起句。这些句子改成「你」或「我们」。小标题保持路标，口语只放在正文的过渡里。温度不是比喻：柜台、申报表、柜员仍然不能当主语。
